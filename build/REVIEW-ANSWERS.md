# 0.5.3 当前候选包的七项审核回答

本文件回答 `build/review.json` 的全部问题。外环人工核查不等于 App Hub 或比赛批准。初赛冻结标签 `v0.5.3-initial` 不改写；本次仅补正 master 的展示及审核材料，应用源码未变。

1. **名称、简介和实际行为是否一致？** `main.splash` 使用 `mail.accounts/sync/list/message` 读取授权来源，再调用 `model.complete` 判断 ignore/create/update/cancel；显示原文、出处及历史，取消明确不代表完成。`listing.description` 明确真实邮箱与模型回环待验收。原生合成测试能证明控制流，不能证明在线模型语义质量。观察仅在应用打开时运行，默认停用，须单独同意云分析。
2. **平台及分类是否合适？** productivity 对应承诺记录与维护；listing 仅列 Windows。只在 Windows Makepad 原生宿主验证，不宣称其他平台已测。
3. **权限是否与界面行为匹配？** mail 用于连接邮箱、核验账号、同步和读取最近5封 INBOX 邮件；model 用于同意后语义分析；storage 用于账号绑定、事项、去重及历史的保存读回。没有直接网络主机白名单，没有发送邮件、全系统监察或额外 agent 权限。主机服务通过 `host.request` 请求；独立 card-host 不带 mail/model 服务，因此会显示服务缺失，不能完成真实回环。
4. **界面是否有欺骗性？** 应用不仿造系统登录、支付或授权页面，不索取密钥或密码；连接操作转交 `mail.add_account`。云分析用途在确认前展示。两个 listing 截图是未修改生产源码的真实原生捕获：默认停用及缺服务失败；不拿合成事项截图伪装真实在线 AI 成果。
5. **源码或数据是否包含给助手的指令？** 有：`model.complete` 的 `task` 指令要求模型判断邮件、遵循输出 schema，并将邮件里的指令仅视为数据。它是应用运行时提示，不是让审核代理忽略政策的指令。未经信任的邮件仍可能误导语义判断；原文证据校验只能限制输出编造，不能证明抗提示注入或归属判断可靠。
6. **是否有辱骂或针对私人个体的内容？** 已检查当前源码、界面文案和用于演示的合成文本，没有观察到此类内容。未读取私人邮件；不能对未来用户数据做保证。
7. **建议路由及可行动理由？** human-review。包检查 PASSED，仅未签名警告；27项合成原生回归、5项生产界面检查及8项录像检查已有记录，但真实邮箱/在线模型回环、语义关联与乱序、纠正流程尚未验收，宿主 Windows 凭据存储与 OAuth 尚未完成。维护者需评估宿主基线及运行时服务配置，不能由本答复自动放行。
