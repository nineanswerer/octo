## 两分钟说明稿

**0:00–0:25｜为什么做。** 我们常常在邮件里答应交纪要、提供名单，之后期限又变了。只做一次摘要很快就会过时。无提醒 Agent 在用户授权的邮箱中持续识别本人承诺，把后续邮件对应到已有事项，让用户随时看到当前状态和依据。

**0:25–0:55｜怎样完成任务。** 我们用五封合成邮件做了真实 POP3 TLS 与 MiniMax-M3 回环。第一封创建纪要，第二封改同一事项的期限，第三封是他人的任务所以不写入，第四封取消纪要，第五封建立独立报名事项。最后得到两个事项：取消的纪要保留两份历史，报名事项仍待处理。重复扫描没有增加记录。

**0:55–1:20｜为什么可以核对。** 模型输出要先通过格式与来源检查再保存。界面保留原文、出处和历史；确认只表示已核对，不代表完成，修正备注不覆盖证据。观察默认停用，启用与云分析同意分开。重启后保存记录仍在，但不会自动恢复观察。

**1:20–1:40｜开发与交付。** MiniMax 编程 Plan 承担明确实现任务，Kimi Code 审查高风险源码，Codex 独立核验宿主与证据。编程套餐和产品模型 API 额度分开。版本通过 GitHub 标签工作流生成证明包，安装说明与验证报告分别给出可复验路径。

**1:40–2:00｜边界。** 当前支持单邮箱、INBOX、最近五封，只有应用打开期间观察。相对期限保留原文。网易 IMAP 缺客户端 ID 的问题未修复，本次真实验收使用 POP3。迟到响应、45秒超时等缺可控注入入口，报告明确未覆盖。视频是脱敏保存结果回放，未追加云调用；我们不把五次通过宣称为准确率。

## 现场与备用

现场先打开固定版本和已授权的测试环境，展示保存记录与核对操作；没有新增模型授权时不要点击“同意本次云分析并开始”。网络或宿主展示故障时播放本视频，明确说明回放范围。[无模型本地查看路径](../docs/RUNNING.md)使用虚构预览数据，不能代替真实回环。
